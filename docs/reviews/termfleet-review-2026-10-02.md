## What it is (short)
A Linux terminal cockpit: a user-local Rust PTY daemon (`src-tauri/src/daemon.rs`, `pty.rs`) owns the terminals over a Unix socket so they survive UI restarts; the UI renders an `alacritty_terminal` grid on a canvas (`vt_grid.rs`, `TerminalCanvas.tsx`) plus a "Magic Canvas" map (`MagicCanvas.tsx`), a session sidebar, agent hooks for Claude/Codex/OpenCode, a phone bridge (`termcontrol/`), and several systemd user watchdogs. It is running right now: UI PID 1879666 (up about 19 h, 216 MB), WebKitWebProcess 1879746 (490 MB), daemon PID 1515447 (up 7.7 days, 266 MB), plus `termcontrol`, io-governor, pane-screen-monitor and pressure-watchdog services.

## Strengths worth keeping
- Daemon socket is owner-only: socket inode `0600` (`daemon_ipc.rs:16-17`), directory `0700` (`daemon.rs:743`), both asserted by tests (`daemon_ipc.rs:80`, `daemon.rs:1229`).
- Protocol handshake: `PROTOCOL_VERSION` (`daemon.rs:23`) is checked and an incompatible daemon is refused, not replaced (`daemon.rs:187-214`).
- TypeScript `strict: true`, zero `as any` / `@ts-ignore` in `src`, only 7 TODO/FIXME in `src` + `src-tauri/src`.
- Atomic temp+rename for workspace saves (`commands.rs:2824-2830`), build lock with `flock` (`scripts/install-release.sh:19-24`), an issue system with an evidence vocabulary (`docs/issue-system.md`).
- Substantial tests: about 230 Rust `#[test]` functions, two Rust integration tests (`daemon_survival.rs`, `grid_live.rs`), 154 Playwright specs.

## Findings

### High
**H1. Disk growth has no retention (S–M).** Observed: `~/.local/share/termfleet/releases` holds **989** immutable release directories (about 19 MB each, 18 GB, from 2026-07-30 to 2026-10-01); `~/.local/share/terminal-workspace/agent-status` holds 20,069 pane-screenshot PNGs (4.8 GB; 15,029 files older than 7 days, oldest 2026-06-19); `sessions/` has 5,383 files (829 MB) plus a 744 MB archive; the build dir `src-tauri/target` is 13 GB. About 37 GB in total on a disk that is 83% full (`/media/endlessblink/data`, 180 GB free). Neither `scripts/install-release.sh` nor `scripts/termfleet-reaper.mjs` prunes releases or screenshots (`rg` finds no retention rule; the reaper only kills idle exited-agent leftovers, TC-055). The screenshots and saved sessions are copies of terminal contents and can hold secrets (files are `664`, directories `775`, the home dir is `750`).
- Fix: a `termfleet-retention.mjs` run by the existing 15-minute maintenance timer, **dry-run first**: keep `current`, `previous`, every release referenced by a running process (`/proc/*/exe` of the UI, daemon and children) and the newest 10; delete PNGs older than 3 days and cap the directory at about 500 MB; compress `sessions-archive-*`; cap `workspace.json.before-*` backups (47 now). Log what was removed.

**H2. CI is red and 78 commits have never been pushed (M).** Observed: the last runs of `ci.yml` on `main` (2026-09-24 16:04 through 2026-09-27 08:47, seven in a row) all failed; the latest (run 36307297607, commit `2732af0`) failed in **"Source-contract gates"** (one second after "Rust warnings gate", so a missing or erroring script, not a slow test) and in the Playwright job's **"Canvas renderer + interaction specs"**. `git status -sb` shows `main` is **ahead of `origin/main` by 78 commits** (2026-09-29 → 2026-10-01), so the TF-069 work has no CI signal at all. The plan itself records 53 red runs before a short green period on 2026-09-23 (`MASTER_PLAN.md`, TF-REL-02).
- Fix: reproduce the two failing steps in a clean worktree (not the shared checkout), fix or consciously remove the gate (the typography gate is already excluded with a comment), push, then require green CI before new features. Add a pre-push hook that runs the CI subset.

**H3. Unrestricted filesystem commands are exposed to the webview (S–M).** `fs_delete` (`commands.rs:2437-2449`) refuses only a path with no parent, so `/home/<user>` or `/media/...` would be removed with `remove_dir_all`; `fs_write_file` (`:2679`) and `fs_read_file` (`:2452`) take any path; `fs_create` (`:2407`), `fs_rename` (`:2422`) likewise; `fs_open_external` (`:2656`) hands any string to `kate`/`xdg-open`/`gio`. The default capability also grants `opener:allow-open-path` (`capabilities/default.json`). The CSP (`tauri.conf.json`) allows `frame-src http: https:` and `style-src 'unsafe-inline'`. Any script that runs in the webview (it renders terminal and agent text and embeds service previews) can read, overwrite or delete any user file. I found no exploit, only the missing boundary.
- Fix: canonicalise every path and confine it to an allow-list of roots (project roots from the workspace, `$HOME` minus dot-directories), reject symlink escapes, send deletes to the trash (or require a native confirmation), narrow `frame-src` to `http://127.0.0.1:*`/`localhost`, and drop `opener:allow-open-path` for a path-validated command. Test: `fs_delete("/home/<user>")`, `../` traversal, symlink out of root.

**H4. Mutex poisoning can cascade through the PTY core (M).** `pty.rs` has 32 `lock().unwrap()` calls in production code (before its test module at line 2828; for example lines 119, 128, 134), and neither `main.rs`, `lib.rs` nor `daemon.rs` installs a panic hook or `catch_unwind`. One panic while a shared lock is held poisons it and every later `lock().unwrap()` panics; the daemon owns the live terminals, so a daemon crash kills the processes inside them. I have not seen such a panic happen; this is a risk assessment from the code shape.
- Fix: switch the shared state to `parking_lot::Mutex` (no poisoning) or `lock().unwrap_or_else(|e| e.into_inner())`; add a panic hook that logs the thread and backtrace to the daemon log; run each session's reader thread under `catch_unwind` and mark only that session failed.

**H5. The app is still reported as sluggish (L, ongoing).** TF-015 is `verifying` since 2026-09-26; the 2026-09-27 hand-off records first workspace paint of about 89 s, a 15-second `perf` capture with WebKitWebProcess at 63% of samples, and `perf_event_paranoid=4` blocking further profiling (`docs/termfleet-responsiveness-dropoff-2026-09-27.md`). Since then commits `545ea1a`, `a940b0c` (a write flood during splash) and `a118d29` landed, and the launcher turned JIT back on (`scripts/termfleet-desktop-launcher.sh:115-122`: the old `JSC_useJIT=false` made scripts 3–6× slower). **Software rendering is still the default**: `LIBGL_ALWAYS_SOFTWARE=1`, `WEBKIT_DISABLE_COMPOSITING_MODE=1`, `WEBKIT_DISABLE_DMABUF_RENDERER=1` (lines 108-110), which means a canvas terminal and a large map are painted on the CPU. Live: WebKitWebProcess is at 490 MB. The daemon behind the UI is a week older than the UI (see M1), so daemon-side fixes may not be live at all.
- Fix: measure on the installed build with the existing latency trace (`scripts/summarize-terminal-latency-trace.mjs`) before and after each change; try hardware GL with only DMA-BUF disabled behind a launcher flag and compare; look at the work done per frame in `MagicCanvas.tsx`/`TerminalCanvas.tsx` (10,593 and 2,395 lines) and at the 1.4 MB `workspace.json` serialisation (`stores/workspace.ts:5452`); keep the JIT setting as is.

### Medium
**M1. Daemon and UI run different builds, with only a one-number protocol check (M).** The daemon (PID 1515447) started 2026-09-24 21:12 from release `57736947a5c5…`; the installed UI is `e106d39…` (2026-10-01). `PROTOCOL_VERSION` is a single `u16` equal to 1 (`daemon.rs:23`) and only equality is checked, so behavioural changes inside the same version are invisible, and fixes in `pty.rs`/`daemon.rs` cannot take effect without restarting the daemon, which kills about 22 live sessions. **M3. Test suite is large but slow to trust (M).** 154 Playwright specs run serially (`playwright.config.ts`: `workers: 1`, `fullyParallel: false`), the config header still says terminals use the web xterm renderer (the canvas renderer is the default now), `reuseExistingServer: true` lets a test attach to whatever listens on :5177, specs pin `/usr/bin/chromium`, there are 96 `verify:*` npm scripts, 35 skip/fixme call sites, and CI runs only `verify:canvas-all` plus two source-contract scripts. `tests/scratch-eval.spec.ts` is untracked. Fix: tiers (fast unit, UI, live-desktop) with tags, one `npm test` that mirrors CI, `reuseExistingServer: !process.env.CI` plus a dedicated port, and a table of which verifiers are required.

**M4. The phone bridge can type into agent terminals (M).** `termcontrol.service` is active on `127.0.0.1:7810`. Authentication is reasonable (scrypt, HMAC cookie, `timingSafeEqual`, key file `0600`: `accounts.mjs`), but after login `sendKey`/`sendToPane` (`server.mjs:184,202`) inject keystrokes and text into live panes. The login rate limiter is keyed by `cf-connecting-ip`/`x-forwarded-for` (`auth.mjs:21-23`), which any client can forge unless the port is reachable only through the trusted proxy; the `Secure` cookie implies an HTTPS front end that I did not inspect; only 8 test files cover the bridge. Fix: key the limiter by socket address unless the peer is the known proxy, add an `Origin` check on POST, add session idle timeout and a confirmation step for destructive keys (Ctrl-C/Ctrl-D, `rm`-looking text), and document how it is exposed.

**M5. Workspace save is atomic but not durable or collision-proof (S).** `workspace_layout_save` (`commands.rs:2824-2830`) writes a fixed `workspace.json.tmp` and renames it, without `fsync`; several dock windows can exist at once (see the "older dock windows can outlive a release restart" comment in `cockpit_snapshot_write`, `commands.rs` after line 2679), so two writers could share the same temp name. The data dir holds 47 `workspace.json.before-*` backups. Fix: unique temp name, `sync_all()` on file and directory, keep the last N backups.

**M6. Login-shell probes and a cwd-relative path (S).** `agent_provider_statuses` (`commands.rs:612-630`) runs `sh -lc "command -v …"` three times per call (each sources the user's profile) and builds the adapter path from `current_dir()` (`scripts/agent-provider-adapter.sh`), which is meaningless for an installed app. Fix: search `PATH` in Rust, cache with a short TTL, resolve the adapter relative to the executable.

**M7. Very large files (L).** `MagicCanvas.tsx` 10,593 lines, `WorkbenchSidebar.tsx` 8,458, `stores/workspace.ts` 5,541, `pty.rs` 5,649, `commands.rs` 3,960 (72 `#[tauri::command]` functions), `vt_grid.rs` 2,696. Fix: split along existing seams, one module per PR, behaviour-neutral, guarded by the specs above.

**M8. Errors lose their type at the IPC edge (S–M).** Commands return `Result<_, String>` (for example every `fs_*`), the UI has 144 `invoke` call sites and 22 empty `catch` handlers. Fix: a serialisable error enum (`kind`, `message`, `retryable`) and a single `invoke` wrapper that logs and surfaces it.

## Concrete sketches
- Path confinement (Rust): `fn confine(path: &str, roots: &[PathBuf]) -> Result<PathBuf, FsError> { let p = fs::canonicalize(path)?; roots.iter().any(|r| p.starts_with(r)).then_some(p).ok_or(FsError::OutsideRoots) }`, called first in every `fs_*` command; `fs_delete` uses `trash::delete` or a native confirmation.
- Retention keep-set: `keep = {current, previous} ∪ {releases of running pids} ∪ newest_10`; everything else older than 14 days is removed; log to `~/.local/share/termfleet/retention.log`; first run with `--dry-run` and a size summary.
- Poison-safe locks: replace `x.lock().unwrap()` with `parking_lot::Mutex` or a helper `fn lock<T>(m: &Mutex<T>) -> MutexGuard<T> { m.lock().unwrap_or_else(|e| e.into_inner()) }`.
