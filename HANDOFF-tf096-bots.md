## 7. Gotchas that burn time

- lean-ctx blocks inline interpreters and heredocs (`python3 -c`, `node -e`, `python3 - <<EOF`, `bash -c`): write the script to a file (Write tool) and run it. `curl` is redirected by a plugin hook: use node `fetch` in a script. `rm -rf` is denied. - The sure gate (`termfleet-sure "1. Root cause ... 2. Confidence: HIGH|MEDIUM|LOW ..."`) blocks code edits until a HIGH answer is recorded since the operator's latest message; a MEDIUM requires doing the research you listed, then re-recording.
- Playwright/Chrome test browsers can hang when the PC is under I/O pressure (they did around midnight on 16 Oct and again 19 Oct). A blank page screenshot timing out = machine problem, not the app; wait/clean stray `ms-playwright` processes. Running many browser test files in parallel flakes (two bot tests failed once, pass alone). Use random ports.
- The agents-app JS is a module: tests cannot call `openBot()`/`chat()` directly; drive the UI. Page is served `no-store`; the service worker is now registered on every load and claims clients immediately.
- Restarting `termcontrol.service` interrupts a bot's current turn (it resumes itself); the unit has memory caps; it does NOT touch terminals. Every behaviour change in `bots.mjs` needs that restart to take effect.
- The context-mode plugin hook redirects WebFetch/curl to its own MCP tools; bots run `claude -p` with your user hooks, so allowlisted tool NAMES matter (done for `ctx_fetch_and_index`, `ctx_search`).
- Android Chrome: `Notification.permission` must be 'granted' for push; "denied" can only be reversed in system settings. Share-target and clipboard-image behaviour on real Android is unverified.
